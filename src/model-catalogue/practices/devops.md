# DevOps

**REGISTER**

A practice of the book *Vibe Coding* as this instance's source register holds it (`SRC-vibe-coding`, version
`2026-10-05`): chapter 7, *DevOps: Closing the Gap Between Development and Operations*. It is added to a declared model
and replaces none. It fits the agile models, Scrum and Kanban, whose gap it closes: "Agile methods accelerate the
development cycle, but they say little about what happens after a sprint produces a working increment."

## Adds

- *Continuous Integration*: every code change is built and tested automatically as soon as it is committed.
- Quality gates on every commit, whoever wrote the code: automated tests, linting and security scans.
- *Continuous Delivery*: the software is kept in a deployable state at all times.
- *Infrastructure as Code*: server configuration, network setup and deployment pipelines kept as version-controlled files.
- *Monitoring and observability*: production behaviour — error rates, latencies, resource usage — fed back to the team.
- One team responsible for the whole lifecycle: build, test, deploy, monitor and respond.

## What it is

DevOps unifies software development and IT operations into one continuous, shared responsibility: the team that writes the
code also runs it — "you build it, you run it". Where developers throw their features over a wall to an operations team,
the wall creates delay, blame and lost information; DevOps removes it. Teams with strong CI/CD, monitoring and shared
ownership deliver faster, with fewer failures, and recover more quickly from incidents. Book chapter 7.
