# Coverage of UC-001 to UC-020 by the backlog

**MEASUREMENT** — 2026-10-16, read on `main` at `93fd4b91` by po-opus with five read-only analysts.

**Method.**
1. Each step, extension and postcondition was read in the original.
2. The items were found with a grep of the use case's identifier in `docs/backlog`.
3. The module files, the code and the tests on `main` were read.
4. A done item was checked against its code and its tests on `main`.
5. A negative grep counted only after the same grep had matched a known positive.

Every step, extension and postcondition of UC-001 to UC-020 is mapped here. There is no UC-009: no file
`docs/use-cases/UC-009-*` exists, and none is invented.
A test marked `todo` counts as no evidence.

Verdicts:
- **item**: an item covers it, and its code and tests are on `main`.
- **open**: an item covers it, and it is not built yet.
- **impl**: code and tests on `main` give it without an item.
- **new**: neither existed, so a new item now covers it.
- **blocked**: it needs a change of a text. The draft named beside it waits for akmaier.

"Unowned" marks code that no module's `folder:` holds, such as `docs/assets/`.

## What holds across the use cases

- **The live pages do not run the module-built site.**
  - `docs/index.html:51` loads `assets/dashboard-app.mjs`, code that no module owns.
  - No HTML page loads MOD-site-frame's `start.mjs`. Its known positive: `dashboard-app.mjs` is found in
    `docs/index.html`.
  - So the prompt bar (UC-019, UC-020 step 6) and the routes built only in `src/` (the Library of UC-004 among them)
    reach no live page.
  - Making `docs/index.html` start the site through `start.mjs` makes old code call a module in place of its own code.
    `WHAT NO MODULE OWNS IS CHANGED BETWEEN JOBS` (SPEC.md:1421) gives that change to a pull request between jobs, not to
    an item. The steps it touches are mapped to the modules that build them.
- **UC-002 step 7 and 7a.** The use case speaks of "the product's process requirements". MOD-product-process and
  MOD-implementation-pages read them from the instance's `SPEC.md`, as gates entered in the declaration's table. The
  code follows the module files (TST-476032). That reading is taken, and the steps count as covered.
