**The retrospective lesson of #811** (record 20261017-2315, `8df5`). A developer runs locally every existing test,
release tests included, that imports a file it changes (`docs/instructions/developers.md`, job rule 6). A pull request
into `sprint/*` runs `mode=rest`, which leaves the release tests out (run 39077163170 of #807); so the item's gate does
not see them, and the sprint's merge into `main` is the first run that does. Of the two failures, the practice workflow
test reaches `process.mjs` through `docs/assets/dashboard/process-view.mjs`; the traceability test reads every tracked
test file, so a new or changed test file is run against it too.
