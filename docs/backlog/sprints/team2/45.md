The concrete evidence path is:

- `src/bridge-http/server.mjs` already dispatches `POST /v1/mail/test` to `handlers.mail["POST /v1/mail/test"]`.
  `src/mail-protocols/index.mjs` now provides that handler through `mailHandlers`.
- Handler input flows as request body `connection` -> `connectionParts()` -> IMAP server, SMTP server, account, password
  and named folders. Missing or non-IMAP Bridge connections fail before any server login.
- IMAP path: `testImap()` constructs `ImapFlow` from the Bridge app package -> `normaliseSecurity()` rejects non-TLS
  configuration before login -> `client.connect()` uses implicit TLS or required STARTTLS with `logger: false` ->
  each named folder goes through `client.mailboxOpen(folder, { readOnly: true })`, which ARC-051 states uses `EXAMINE`
  -> counts come from `opened.exists` -> `client.list({ listOnly: true })` recognises `\Drafts` and `\Sent`.
- SMTP path: `testSmtp()` constructs nodemailer from the Bridge app package with `secure: true` or `requireTLS: true`,
  `logger: false` and `debug: false` -> `transport.verify()` logs in and disconnects without `MAIL`, `RCPT` or `DATA`.
- Error mapping stays at the failure node: absent TLS becomes `no-encryption` naming IMAP or SMTP with no login sent;
  refused credentials become `login-refused` with the server's answer; a missing named folder becomes `not-found`; all
  other mail-server failures become `upstream-failed`.

Counter-proof notes for the pull request/final report:

- `TST-420001`: before the handler existed, the test failed at import; during implementation it also failed when the
  IMAP fixture namespace was not explicit, because `Reports` was not counted as expected.
- `TST-420002`: the assertion checks the exact protocol commands: named folders must be opened by `EXAMINE`, and any
  `SELECT`, `STORE`, `COPY`, `MOVE`, `EXPUNGE` or SMTP `MAIL`/`RCPT`/`DATA` command fails the test.
- `TST-420003`: the no-STARTTLS fixture passed only after the handler mapped the library failure to `no-encryption` and
  the recorded commands proved no `LOGIN`, `AUTHENTICATE` or `AUTH` carried the marker password before TLS.
- `TST-420004`: an implementation that let imapflow's default `AUTHENTICATE PLAIN` path pass without the fixture
  checking the password made this test report a missing rejection; forcing the checked LOGIN path made the refused
  server answer surface as `login-refused`.
- `TST-420005`: before mapped mail failures were preserved through the outer handler catch, a missing folder was
  remapped to `upstream-failed`; the test now fails unless the named folder is preserved as `not-found`.
