  counts. The file says to read them from GitHub's documentation. The Developer reads them there and names each page in the
  pull request. The known positive is one query against this repository on github.com with the Developer's own `gh` login,
  recorded in the pull request; the tests themselves use fixtures and reach no network.
- **The address of the batch.** It goes to `/graphql` on the same API origin the GitHub adapter's REST requests use, with
  the same token, through the repository hosts' existing request helper. No new `fetch` is added, so
  `tests/test_no_backend.py` needs no change.
- **A file the batch could not give.** A file GraphQL answers as truncated or binary, or not at all, is fetched by its
  own `read`.
- **A batch request that fails.** If the server answers anything other than a failure `readSnapshot` itself knows
  (`TokenRefused`, `PermissionMissing`, `RateLimited`, `Unreachable`), nothing is read ahead and each `read` fetches its
  file as before. A server that serves no `/graphql` therefore changes nothing.
- **The regression test's bound.** A trace graph over a fixture host of 1,332 files makes at most 2 + ⌈1,332 / B⌉
  requests, where B is the documented number of files per query the Developer names. Today it makes 2 + 1,332.
