**Questions for akmaier.** Each blocks an item. Each could not be settled from the texts, because the answer is an
interface between two modules that no accepted file states.
1. **ITM-504, the prompt bar.** It offers "an agent on a Bridge its store keeps" and runs the job with `runOnTab`, which
   takes Bridge handles. A handle is made with MOD-bridge-client's `bridgeAt` from settings that only `settingsOf` makes
   from what the store keeps, as the review pages do (`src/review-pages/jobs.mjs`, `connectionsOf`). MOD-prompt-bar's file
   uses `bridgeAt` but not `settingsOf`. May MOD-prompt-bar use `MOD-bridge-client.settingsOf`?
2. **ITM-486, the tools.** MOD-job-runner offers only the tools "that the page's subject does not refuse", and
   MOD-prompt-bar's `Subject.refuses` names them. No file says how `refuses` reaches the runner. Should it travel as a job
   parameter `refuses`, set by the bar, as `entry` does?
3. **ITM-494, a subagent's routes.** `routesFor(participant, product, needs)` is to give a subagent "the routes of that
   participant" its route names, but it is given no register in which to find that participant. Should it take the
   participants, or the starter itself?
4. **A handed-over task.** MOD-runtimes, MOD-workflow-entries and MOD-bridge-jobs run a handed-over job "with the task as
   its instruction". The kinds such work goes to — `implement`, `fix-bug`, `write-tests` — name no `instruction` recipe,
   so the task reaches no part of their prompt. Should those kinds name `instruction`?
