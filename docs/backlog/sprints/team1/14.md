## Questions for akmaier

Named by the Product Owner po-opus during the sprint; each waits for the sprint's end
(`docs/instructions/product-owner.md`, No discussion during the sprint).

- Which files under `tests/` must declare a test? MOD-test-document's Data makes every file under a folder named `test`,
  `tests` or `__tests__` a test file, and MOD-job-runner's `test-declarations` reports a test file a branch adds that
  declares none (ITM-386, #341). So a fixture or a helper a participant adds under `tests/` — a JSON file among them — is
  reported, and its participant cannot fix it. Neither file says more.
- Is a candidate that keeps an existing requirement's name and changes its rule a duplicate or a change?
  `EXACT DUPLICATES ARE FOUND WITHOUT A MODEL` makes it a duplicate — "name or normalised rule text equals" —, and
  `A CHANGE IS PROPOSED UNDER THE EXISTING NAME` a change; `classifyCandidates` follows the first (ITM-303, #342), where
  one line would switch it. Both are binding SPEC sentences; the approval's rationale of the first speaks of "same name,
  same normalised text".
- Which key classifies a drafted use case, architecture file, backlog item or test? MOD-documents' `Candidate` names the
  key of a requirement only — its name and its rule —, so the check `candidate-classes`, which seven kinds name, classifies
  drafts of requirements alone (ITM-387, #347), and UC-007 6a — a use case with the same goal already exists, and Agent M
  proposes a change to that file — has no key to find that use case by. No item is written before this is answered.
