## Goal

UC-003 through the dashboard: store an OpenAI-compatible or Anthropic endpoint, model and optional key in this
browser, send one short test request, show success or an actionable diagnosis, retain a refused key until changed
or cleared, and really remove cleared configuration. Its local-model alternative sends the test through the
paired Bridge, including the HTTPS route UC-044 supplies for Safari. No credential enters a URL, cookie or repository.

Scope is configuration and testing, not running arbitrary jobs, the full Bridge application, CLI discovery,
mail, cluster probes, CI execution or tunnel provisioning. Naming CI and Bridge as alternative runtimes does not
require implementing their job execution. A models-list response does not satisfy UC-003's short test request.

## Bridge contract proposal — prerequisite, not an accepted design

UC-003 alternative 2a requires step 4's short test request through the Bridge. The accepted
`MOD-bridge-http` route table, `MOD-bridge-client.probe` and `MOD-bridge-jobs.jobHandlers` only offer
`endpoint-models`, which lists served models. Their ask operation addresses a coding agent, not an endpoint
configuration. `MOD-endpoint-calls` also excludes calling a local server reached through the Bridge from its
direct driver responsibility. These texts do not yet specify an end-to-end operation for UC-003's test.

Before the Bridge implementation items start, prepare the smallest architecture refinement for akmaier's acceptance:

- one endpoint-test operation in the common protocol, with its method/path, endpoint URL, kind, model and optional
  key as JSON body fields, success/diagnosis answer and named transport errors;
- its client operation, using the pairing token and optional jump-host login in headers, never in URLs;
- its Bridge handler, which calls the short test on the Bridge machine, forwards provider errors and retains no
  endpoint settings or key on disk; an accepted use of MOD-endpoint-calls for this Node test;
- the composition point that registers this handler in a runnable Bridge, and the settings page's minimal pairing
  handoff to UC-044. If an existing UC-044 delivery supplies these, record its exact merged revision rather than
  building a second server or provisioning path.

The affected module files are MOD-bridge-http, MOD-bridge-client, MOD-bridge-jobs, MOD-endpoint-calls,
MOD-desktop-shell and MOD-settings-pages; adjust their parent decision only if the agreed module responsibilities require it. This plan supplies the proposal's
scope but changes none of their accepted files. The accepted revision determines the final operation name and exact
item acceptance before selection. No SPEC change is needed merely to add the missing transport contract.
