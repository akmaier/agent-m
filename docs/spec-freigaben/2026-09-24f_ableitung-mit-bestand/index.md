# SPEC approvals — queue 2026-09-24f · derivation with the existing requirements

**PO, 2026-09-24:** *"UC-005 needs to make sure there is a deduplication pass and which requirements
already exist and need to be modified. Any derivation of new requirements should also have the old
ones in context and modify them instead of duplicating them."*

One entry, appended to §3. Every derivation sees the existing requirements. Nothing is left out of
the context silently. Each candidate is classified as new, change, duplicate or conflict. Exact
duplicates are found without a model; the model's classification is measured and shown to a person.
A change keeps the existing name, a duplicate adds a source, a conflict waits for a person.
Candidates are merged among themselves first.

**Impact analysis:** no existing rule changes. The new rules use `A REQUIREMENT IS NOT CHANGED WITHOUT
AN IMPACT LIST`, `NO PROPOSAL WITHOUT THE CURRENT TEXT BESIDE IT` and `A SOURCE DECLARES ITS
AUTHORITY` as they stand. UC-005 is updated with this queue. UC-012 (issue → SPEC change) already
proposes changes to existing requirements and stays correct.
