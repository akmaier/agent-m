# A requirement says whether it binds the product or the way it is built

Your distinction, turned into a field: requirement sources contain rules *on the product* and rules
*on the development process*. IEC 62304 has both kinds. Its safety class is determined by what
the product can do to a patient, which makes it a fact about the product. What the class demands,
from documented unit verification to traceability and risk management, is a set of process
obligations.

Only process requirements change how Agent M organises the work (entry 02). Without this field
Agent M could not tell which requirements add gates and which are simply to be built.
