# Decisions of the Product Owner for D.AI.Y

> Draft. Written from mrh's statements of 2026-10-25; mrh edits and confirms it before the source is registered.

1. D.AI.Y is a test project and is not going to be published. One purpose of it is to see how Agent M works with sources.
2. What the team has so far is input only: Requirements v0.4, Personas v0.5, the prototype and the implementation plan. The requirements are produced the way Agent M produces them.
3. Requirements evolve the way chapter 8 of the book *Vibe Coding* describes: elicitation, specification, validation and verification, evolution.
4. The rules of the registered sources are treated as if D.AI.Y were released in Germany. *(proposed by Claude, not yet confirmed)*
5. For building law and neighbour law the state of Bavaria applies.
6. Technical norms cannot be bought for a test project; freely available laws and guidance stand in for them. The sources are kept as extracts of the relevant parts.
7. The whole development cycle is run through by 2026-11-05. The reviews are done quickly, with AI support on the team's side, outside Agent M.
